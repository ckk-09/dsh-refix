## 机制要点（P1 落定）

1. **三通道巡检触发**：事件即时（dynamic-package / dynamic-retract）+ 周期（timer 服务 `ctx.interval`，fiber effect，stop 自动清理）+ 按需（`refix_patrol` 工具）。生产 15s，按需巡检补足了实时性。
2. **health 探针约定**：§5 策略表明载"宿主方法抛错"的检测方法是"巡检 invoke 失败"。探针只 invoke 名为 `health` 的 handler（无副作用的受检约定），返回 `method-not-found` 的插件记入 skip 集合不再重复探测。这是对 B2 只读清单的一处**显式、有界例外**，依据即需求自身。
3. **进行中状态白名单**：`starting-host / client-pending / awaiting-approval` 视为版本切换中，不报 run 消失——这是 update/审批流转不误报的关键。

## 踩坑记录（已修复）

- **runner 时序坑**：`stop()` 与 `update()` 都是**先 retract（emit 事件）→ 后更新 `latestRun.status`**。事件触发的巡检在 emit 时刻看到 status 仍是 `running`，初版"status==='stopped' 才报 run 消失"的条件漏报。修复：改为白名单抑制进行中状态（凡消失、且不在进行中 → 报告），停机在事件时刻即被正确捕获。
