## 关键设计决策（啃透机制后的落点）

1. **agent 解析**：`run/stop/snapshot` 都需要 `Agent`，但插件宿主半天然不知道自己属于哪个会话。解法：**不需要知道**——`inventory()` 每行自带 `agentId`（插件归属会话），修复时用 `ctx.agents.get(row.agentId)` 解析出 Agent 即可通过 runner 的所有权校验（`plugin.sessionId === agent.id`）。归属会话已关闭 → 如实报告"无法修复"。
2. **沙箱边界**：host 半只能用 `ctx.get/on/provide/effect` + `harness` + inject 声明的服务；`dynamicCordisRunner`/`cordisInspect`/`agents`/`timer` 均为 root 级服务，可被动态包 inject（这是 B2/B3 约束能成立的前提）。
3. **周期巡检**：沙箱禁用 `setInterval`，用 `inject:['timer']` + `ctx.interval(fn, ms)`（fiber effect，stop 时自动清理）——P1 落地。
4. **诊断输出**：模型侧拉取（`refix_report` 工具）+ `Refix` inspect provider；不做主动 steer（v1 保持最小面）。

## 踩坑记录（已修复）

- `ctx.effect(ctx.cordisInspect.register(...))` 把 register 返回的 **disposer 当成 effect body 立即执行**，注册即被撤销。正确形态是传 thunk：`ctx.effect(() => register(...))`（tool-cordis 源码同款写法）。用双探针（直接注册 vs effect 包装）定位。
